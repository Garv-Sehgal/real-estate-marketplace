CHAPTER 2: INTRODUCTION TO SOFTWARE


2.1 Project Introduction

The **Real Estate Marketplace Platform** is a modern, high-performance web platform designed to digitize, secure, and streamline property transactions and user interactions. Built as a mobile-installable Progressive Web Application (PWA) with a decoupled backend API architecture, the software provides a fast, native-app-like experience on web and mobile devices.

Unlike legacy real estate portals that act merely as passive advertising directories, this system introduces active, real-time engagement and secure communication channels:

  1. Interactive Multi-Step Listing Stepper: Landlords and agents are guided through a structured form validation flow, capturing property pricing, amenities, GPS coordinates, and verification proofs.
  2. Direct Google Maps Navigation: Properties are mapped using exact latitudes and longitudes, offering immediate spatial context.
  3. Grid Comparison Matrix: Users can select up to four properties and compare their pricing models, carpet area, BHK configurations, and nine core amenities side-by-side.
  4. Client-Side CryptoJS Cryptography: Communication between buyers and owners is processed using a zero-knowledge architectural model. Chats are encrypted in the browser, ensuring the central database stores only encrypted ciphertext.
  5. Integrated Visit Scheduler: Enforces a structured scheduling workflow, allowing buyers to request physical site visits directly from the chat timeline, with real-time status transitions.

2.2 Problem Statement

Traditional real estate portals in the regional Indian market suffer from several structural, technological, and security limitations:

  • Listing Fraud and Fake Accounts: Legacy platforms rarely enforce identification checks or property deed verification. Fraudulent agents frequently upload fake listings using copied images, leading to bait-and-switch scams.
  • Passive, High-Friction Communication Systems: Communications are usually routed through public email addresses or shared phone numbers, exposing users to unsolicited calls and spam. Instant negotiations are hard to manage within the platform, forcing users to external applications like WhatsApp where context is lost.
  • Privacy and Database Security Breaches: Central databases store private chat logs, negotiation records, and scheduling details in plain text. A database breach could expose sensitive user data, transaction records, and communication histories.
  • Rigid Layout Structures and Slow Search Speeds: Lack of fluid mobile interfaces, sluggish search times under high database volumes, and the absence of interactive property comparison grids increase transaction friction.

The proposed software addresses these challenges by introducing a secure, verified, and real-time PWA marketplace:

  • Strict Identity and Document Verification: Landlords and agents must upload government IDs and ownership proofs, which are audited through an Admin moderation panel. Listings remain "pending" until approved by an administrator, mitigating fraud.
  • Decoupled Next.js 16 and Express 5 Architecture: The client is built using Next.js 16, utilizing optimized client-side state handling and TailwindCSS v4. The backend is built on Express 5, using MongoDB as a flexible schema-enforced NoSQL document store.
  • Symmetric Client-Side AES Cryptography: The platform uses client-side encryption for private messaging. The backend only acts as a zero-knowledge relay, storing encrypted ciphertext. Decryption occurs only in the authorized clients' browsers.
  • Integrated Visit Scheduler: Enables immediate booking of site visits within the chat room. The state transition flow (pending -> confirmed/rejected/rescheduled) is dynamically updated on both parties' dashboards.

2.4 Objectives

The primary engineering and operational objectives of the platform are to:

  1. Prevent Listing Fraud: Implement robust multi-step listing uploads, requiring deeds and identification documents, and configure an administrative moderation workflow to screen properties before they go public.
  2. Protect User Privacy: Build a zero-knowledge message broker where chat contents are encrypted in the client’s browser, preventing database operators from reading negotiations.
  3. Reduce Communication Friction: Integrate persistent WebSocket connections (Socket.IO) to support instant chat, typing states, and in-chat visit scheduling workflows.
  4. Simplify Discovery and Comparison: Build multi-criteria search filters and an interactive side-by-side grid comparison matrix to help buyers evaluate listings.
  5. Deliver PWA Performance: Optimize client-side rendering speed, implement responsive mobile layouts, and ensure quick API response times.

2.5 Functional and Non-Functional Requirements

The software is designed to satisfy strict functional and non-functional requirements to ensure reliability, security, and performance.
