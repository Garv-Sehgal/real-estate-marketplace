5.1 Development Commands Used During Training

During the onboarding and integration phases at SPRWork Infosolutions, several command-line tools were utilized to initialize environments, orchestrate servers, and manage package modules. The core commands are detailed below:

5.1.1 Environment Setup and Package Management

To initialize a clean local workspace and manage framework dependencies, the Node Package Manager (NPM) was used: 

# Initialize a new package manifest in a directory
npm init -y

# Install production-ready modules (Express, Mongoose, Socket.IO)
npm install express mongoose socket.io bcryptjs jsonwebtoken dotenv cors

# Install client-side styling and icon modules
npm install lucide-react country-state-city crypto-js

# Install development helpers (Nodemon for server hot-reloading)
npm install --save-dev nodemon

5.1.2 Database and Server Execution

To run development instances and verify cluster connections, standard script commands were executed: 

# Start the Express server locally in development mode (hot-reloading)
npm run dev

# Start the server in production mode
npm start

# Run the local Next.js development server
npm run dev

5.4 Glossary

Below is a glossary of key software engineering terms referenced throughout the training report:

  • Asynchronous Programming: A design pattern where execution is non-blocking, allowing long-running requests (like database queries or API fetches) to run in the background.
  • Client-Side Rendering (CSR): A web development process where page layouts are rendered directly in the user’s browser using client-side JavaScript, improving interaction speeds.
  • Decoupled Architecture: An architectural pattern that separates frontend interfaces from backend APIs, allowing them to scale and be maintained independently.
  • Key Derivation Function (KDF): A cryptographic process that derives highly secure keys from input parameters (such as conversation IDs and salts) for use in encryption.
  • NoSQL Database: A non-relational database engine (such as MongoDB) that stores data in flexible, document-based schemas rather than static tables.
  • Zero-Knowledge Architecture: A security model where a server brokers and stores encrypted information without having access to the decryption keys, ensuring user privacy.
